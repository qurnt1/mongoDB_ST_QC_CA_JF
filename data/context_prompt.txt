1. SCHÉMA EXACT DES COLLECTIONS (MODÈLE DOCUMENT ACTUEL)

---

La base 'Paris2055' contient 3 collections principales construites par un ETL Python spécifique :

============================================================
1. Collection 'lignes'
============================================================

Une ligne de transport = 1 document.
Ce document agrège toutes les données relatives à la ligne (arrêts, trafic, véhicules).

Champs de base :
* id_ligne              : int
* nom_ligne             : string  (ex : "B2", "M14")
* type                  : string  (ex : "Bus", "Tramway", "Metro")
* frequentation_moyenne : float | null

Caches pré-calculés (À UTILISER EN PRIORITÉ pour la performance) :
* co2_moyen_ligne : float | null
  (Moyenne pré-calculée des émissions de CO2 sur la ligne).

* stats_trafic : {
    "total_retard"    : float,  # Somme des retards en minutes
    "nb_trajets"      : int,    # Nombre de trajets enregistrés
    "moyenne_precalc" : float   # Moyenne exacte (total_retard / nb_trajets)
  } | absent

* vehicules_cache : [
    {
      "id_vehicule"     : int,
      "immatriculation" : string,
      "type_vehicule"   : string | null   # ex : "Electrique", "Diesel"
    },
    ...
  ] | absent

* chauffeurs_cache : [
    {
      "id_chauffeur"  : int,
      "nom_chauffeur" : string
    },
    ...
  ] | absent

Détails embarqués (Tableaux volumineux) :

* arrets : [
    {
      "id_arret"     : int,
      "nom"          : string,
      "latitude"     : float | null,
      "longitude"    : float | null,
      "quartiers"    : [ { "id_quartier": int, "nom": string }, ... ] | absent,
      "capteurs_ids" : [ int, ... ] | absent,
      "horaires"     : [
          {
            "heure_prevue"      : date,          # Date ISODate
            "passagers_estimes" : int | null,
            "vehicule" : {
                "id_vehicule"         : int,
                "type_vehicule"       : string | null,
                "immatriculation"     : string | null,
                "id_ligne_officielle" : int | null
            } | absent
          },
          ...
      ] | absent
    },
    ...
  ]

* trafic : [
    {
      "id_trafic"      : int,
      "horodatage"     : date,
      "retard_minutes" : int | null,
      "incidents"      : [
          {
            "id_incident" : int,
            "description" : string | null,
            "gravite"     : string | int | null
          },
          ...
      ] | absent
    },
    ...
  ]

============================================================
2. Collection 'capteurs'
============================================================

Un capteur physique = 1 document.

Champs principaux :
* id_capteur   : int
* type_capteur : string   # ex : "CO2", "Bruit", "Temperature"

Localisation :
* position : {
    "type"        : "Point",
    "coordinates" : [ longitude, latitude ]
  } | absent

Rattachement (Dénormalisé) :
* arret : {
    "id_arret"  : int,
    "nom"       : string | null,
    "id_ligne"  : int | null,
    "nom_ligne" : string | null
  } | absent

Historique des mesures :
* mesures : [
    {
      "id_mesure"  : int | null,
      "horodatage" : date | null,
      "valeur"     : float | null,
      "unite"      : string | null  # ex : "ppm", "dB", "°C"
    },
    ...
  ]

============================================================
3. Collection 'quartiers'
============================================================

Un quartier géographique = 1 document.

Champs principaux :
* id_quartier : int
* nom         : string

Géométrie :
* geom : {
    "type"        : "Polygon" | "MultiPolygon",
    "coordinates" : [...]
  } | absent

Contenu :
* arrets : [
    {
      "id_arret"  : int,
      "nom"       : string,
      "id_ligne"  : int | null,
      "nom_ligne" : string | null,
      "latitude"  : float | null,
      "longitude" : float | null
    },
    ...
  ] | absent

2. RÈGLES DE SÉLECTION DE LA COLLECTION

---

* Utilise "lignes" pour : Retards, Trafic, Ponctualité, Véhicules, Chauffeurs, Fréquentation, Incidents.
* Utilise "capteurs" pour : Pollution, CO2 (détail), Bruit, Température, analyse fine des mesures.
* Utilise "quartiers" pour : Densité d'arrêts, analyse spatiale par zone (GeoJSON).

---

3. STRATÉGIES D'OPTIMISATION (CRITIQUE)

---

1. Stats Trafic & Retards :
   NE RECALCULE PAS les moyennes si ce n'est pas nécessaire.
   Utilise `stats_trafic.moyenne_precalc` pour la moyenne par ligne.
   Utilise `stats_trafic.total_retard` pour les sommes.

2. Véhicules & Chauffeurs :
   Ces entités n'ont pas de collection propre.
   Utilise `lignes.vehicules_cache` pour compter ou lister les véhicules.
   Utilise `lignes.chauffeurs_cache` pour les chauffeurs.

3. CO2 :
   Pour une vue par ligne : Utilise `lignes.co2_moyen_ligne`.
   Pour une vue détaillée ou par capteur : Utilise `capteurs.mesures`.

4. Incidents :
   Ils sont imbriqués dans `lignes.trafic`.
   Pour compter les incidents :
   `{ $project: { nb_incidents: { $size: { $ifNull: ["$trafic.incidents", []] } } } }` n'est pas suffisant car `trafic` est un tableau de trajets.
   Il faut souvent : `$unwind "$trafic"` puis vérifier si `$trafic.incidents` existe et n'est pas vide.

5. Géospatial :
   Les collections `quartiers` (index sur `geom`) et `capteurs` (index sur `position`) supportent `$geoIntersects` et `$near`.
